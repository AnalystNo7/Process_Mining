# 04. Пользовательский интерфейс

## Общие принципы

- **UI-библиотека:** Ant Design 5.x. Не использовать кастомные компоненты, где есть готовый AntD.
- **Язык интерфейса:** русский по умолчанию. Все label/placeholder/messages — на русском.
- **Тема:** светлая по умолчанию (AntD ConfigProvider), поддержка тёмной — опционально (на будущее).
- **Layout:** боковое меню (Sider) + шапка (Header) + основной контент (Content).
- **Маршрутизация:** react-router-dom v6, layouts через `<Outlet />`.
- **Локализация дат:** dayjs + Russian locale, формат `DD.MM.YYYY HH:mm`.
- **Числа:** `Intl.NumberFormat('ru-RU')`, разделитель — пробел (`1 328`).
- **Длительности:** `Xд Yч Zм` для отображения (например, `20д 17ч 29м`).

## Структура страниц (routes)

```
/login                           — экран входа
/                                — редирект на /projects

/projects                        — список проектов
/projects/new                    — создать проект
/projects/:id                    — обзор проекта
/projects/:id/settings           — настройки проекта (название, описание)
/projects/:id/role-mapping       — редактор маппинга ролей
/projects/:id/sla-rules          — редактор SLA-правил
/projects/:id/upload-templates   — шаблоны загрузки

/projects/:id/datasets/upload    — мастер загрузки физ. датасета
/projects/:id/datasets/:dsId     — детали физ. датасета

/projects/:id/virtual/:vdId      — обзор виртуального датасета (стартовый дашборд)
/projects/:id/virtual/:vdId/dashboards/:dashId   — конкретный дашборд
/projects/:id/virtual/:vdId/slices               — список срезов
/projects/:id/virtual/:vdId/explore              — exploration view (граф, кейсы, drill-down)

/admin/users                     — управление пользователями (только админ)
/admin/global-roles              — глобальный шаблон ролей
/admin/audit-log                 — журнал действий

/me                              — профиль пользователя
```

## Экраны

### 1. Login (`/login`)

Простая форма по центру экрана:
- Поле `Логин`
- Поле `Пароль`
- Чекбокс `Войти через LDAP/AD` (опционально, если LDAP сконфигурирован)
- Кнопка `Войти`
- Сообщение об ошибке (если 401)

После успешного входа → редирект на `/projects` (или на `?redirect=` если был).

### 3. Создание проекта (`/projects/new`)

Простая форма:
- Название (required)
- Описание (textarea, optional)
- Кнопка `Создать` → редирект на `/projects/:id`

### 4. Обзор проекта (`/projects/:id`)

Главная страница проекта. Tab-структура:

**Вкладка "Обзор":**
- Карточки KPI: количество датасетов, виртуальных датасетов, дашбордов, аннотаций.
- Список последних дашбордов с превью.
- Кнопки `+ Загрузить датасет`, `+ Создать дашборд`.

**Вкладка "Физические датасеты":**
- Таблица: Название | Файл | Размер | Кейсов | Событий | Период | Health | Загрузил | Дата | Действия
- Health отображается цветной меткой (зелёный/жёлтый/красный) с тултипом-отчётом.
- Действия: открыть, создать виртуальный датасет, удалить.

**Вкладка "Виртуальные датасеты":**
- Таблица: Название | Физ.датасет | Маппинг (версия) | SLA правил | Дашбордов | Создал | Дата
- Действия: открыть, удалить.

**Вкладка "Маппинг ролей":**
- Кнопка `Редактировать маппинг` → ведёт на `/role-mapping`.
- Превью текущей версии: список ролей с количеством подразделений.

**Вкладка "SLA":**
- Список SLA-правил в виде таблицы (см. ниже).

**Вкладка "Настройки":**
- Редактирование названия/описания.
- Кнопка `Удалить проект` (только создатель и админ, с подтверждением).

### 5. Мастер загрузки физ. датасета (`/projects/:id/datasets/upload`)

AntD `Steps`-компонент, 3 шага:

**Шаг 1: Выбор файла**
- `Upload` AntD-компонент (drag & drop). Принимает `.xlsx`, `.xls`.
- После выбора → отправляется на `/preview`, показывается прогресс-бар.
- Когда preview готов → переход на шаг 2.

**Шаг 2: Маппинг колонок**
- Таблица: Стандартное поле | Колонка в файле (dropdown) | Превью значений | Обязательно?

| Стандартное поле       | Колонка в файле                        | Превью                | * |
|------------------------|----------------------------------------|-----------------------|---|
| Идентификатор кейса    | [doc_id ▾]                             | DOC-00001-...         | ✓ |
| Операция               | [Операция ▾]                           | Согл. Юр.управления   | ✓ |
| Начало операции        | [in_progress_datetime ▾]               | 09.01.2025 11:53      | ✓ |
| Окончание операции     | [completed_datetime ▾]                 | 09.01.2025 12:00      | ✓ |
| Исполнитель            | [task_user ▾]                          | Сотрудник 103         |   |
| Подразделение          | [task_user_department ▾]               | Финансовое управление |   |

- Под основной таблицей — раздел "Дополнительные атрибуты" с возможностью добавить произвольные колонки в `attributes` (свободный маппинг "имя_атрибута → колонка_файла").
- Кнопка `Применить шаблон загрузки` (dropdown с существующими шаблонами проекта).
- Чекбокс `Сохранить как шаблон` (внизу).
- Кнопка `Загрузить` → отправляется на `POST /physical-datasets`, переход на шаг 3.

**Шаг 3: Прогресс и результат**
- Прогресс-бар расчёта (через polling `GET /tasks/{id}`).
- После завершения:
  - Если success: показать сводку (кейсов, событий, health) + кнопка `Создать виртуальный датасет` (предлагается автоматически).
  - Если error: показать сообщение + детали.

### 6. Детали физ. датасета (`/projects/:id/datasets/:dsId`)

- Метаданные (название, файл, размер, период, статистика).
- **Health report**: подробная таблица проверок с цветными метками и описаниями.
- **Список виртуальных датасетов**, созданных на основе этого физ.датасета.
- Кнопки `+ Создать виртуальный датасет`, `Скачать оригинальный файл`, `Удалить`.

Кнопка `+ Добавить правило` открывает модалку с формой:

## Каталог виджетов

Все виджеты, поддерживаемые в MVP. Каждый — отдельный React-компонент, получает `widget_id` и сам запрашивает данные через `GET /widgets/{id}/data`.

### `kpi_card` — KPI-карточка

**Config:**
```json
{
  "metric": "total_cases | total_events | unique_activities | unique_resources | unique_departments | global_rework_pct | variability_pct | mean_occurrence_pct | avg_case_duration_seconds | sla_compliance_pct | cases_with_rework | cases_without_rework",
  "format": "number | percent | duration | datetime",
  "icon": "FileTextOutlined | ClockCircleOutlined | UserOutlined | ...",  // optional
  "show_comparison": false  // на будущее: сравнение с предыдущим периодом
}
```

**Render:** большая цифра по центру + подпись (title виджета) + иконка слева.

### `bar_chart` — Столбчатая диаграмма

**Config:**
```json
{
  "data_source": "monthly_dynamics | top_departments | top_resources | top_activities | top_rework",
  "x_axis": "month | department | resource | activity",
  "y_axis": "n_events | n_cases | rework_pct | avg_duration",
  "show_line_overlay": true,    // как у Газпрома: bars + линия avg_duration
  "line_metric": "avg_sojourn_seconds",
  "limit": 20,
  "horizontal": false
}
```

**Render:** Plotly bar chart, опционально с линией поверх (combined chart).

### `line_chart` — Линейная диаграмма

**Config:** аналогично bar_chart, тип линейный.

### `heatmap` — Тепловая карта

**Config:**
```json
{
  "x_axis": "month | week",
```

## Состояние и React Query

- **React Query** для всех серверных запросов. Кэширование по `(endpoint, params)`.
- Инвалидация кэша при мутациях: при создании виртуального датасета — инвалидировать список виртуальных датасетов проекта.
- **Optimistic updates** для лёгких операций (создание аннотации, переименование).
- **Zustand** для локального UI-состояния: открытые modals, выбранные элементы, состояние конструктора дашбордов, текущие фильтры дашборда (до сохранения).

## Обработка ошибок и загрузок

- **Loading skeletons** (AntD `Skeleton`) во время загрузки данных виджета.
- **Empty states** с иллюстрацией и CTA-кнопкой ("Загрузите первый датасет").
- **Error boundaries** на уровне страниц + per-widget — чтобы один сломанный виджет не ронял весь дашборд.
- **Toast-уведомления** (AntD `notification`) для уведомлений: загрузка завершена, ошибка сохранения, и т.д.
- **WebSocket или polling для фоновых задач** — индикатор прогресса в шапке (badge с количеством фоновых задач).

## Адаптивность и доступность

- Минимальная ширина экрана: 1280px (десктоп-only).
- Дашборды масштабируются по ширине через grid.
- Доступность: `aria-*` атрибуты, keyboard navigation для модалок и таблиц (AntD из коробки).

## Производительность

- Виджеты загружают данные **лениво** при попадании в viewport (IntersectionObserver).
- Тяжёлые компоненты (Cytoscape граф) — lazy-loaded через React.lazy.
- Большие таблицы — виртуальная прокрутка (AntD `Table` virtual mode).
- Дебаунс на фильтрах (300ms) перед отправкой запроса.
