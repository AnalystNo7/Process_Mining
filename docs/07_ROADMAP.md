# 07. Roadmap разработки

## Цель документа

Определить **порядок выполнения задач** для Claude Code так, чтобы:
1. Каждая задача опиралась только на ранее реализованное.
2. После каждой "вехи" получался работающий артефакт, который можно проверить.
3. Риски обнаруживались как можно раньше.

## Принципы планирования

1. **Сверху вниз — снизу вверх.** Сначала фундамент (БД, миграции, базовые модели). Потом домен-логика (чистые алгоритмы, тестируются без UI). Потом API. В конце — UI.
2. **Golden tests первыми.** Сначала проверяем, что алгоритмы возвращают правильные цифры (без API/UI). Это даёт уверенность в фундаменте.
3. **MVP — слоями.** Каждый слой может работать сам по себе с базовым тестовым покрытием.

## Фазы разработки

### Фаза 1: Фундамент (`T01-T08`)

Цель: проект развёрнут локально, БД работает, базовая аутентификация работает.

После Фазы 1: можно зарегистрировать пользователя и войти.

### Фаза 2: Загрузка данных и виртуальные датасеты (`T09-T16`)

Цель: можно загрузить xlsx-файл, увидеть его в системе, создать виртуальный датасет.

После Фазы 2: данные в БД, базовые KPI считаются.

### Фаза 3: Аналитика (`T17-T24`)

Цель: алгоритмы process mining работают, отдают цифры через API.

После Фазы 3: golden tests все зелёные, API возвращает ping-pong / графы / варианты.

### Фаза 4: Дашборды и UI (`T25-T32`)

Цель: пользователь видит KPI, графики, граф процесса в браузере.

После Фазы 4: можно работать с системой как с продуктом.

### Фаза 5: Продвинутые фичи (`T33-T40`)

Цель: SLA-комплаенс, конструктор дашбордов, аннотации, BPMN-экспорт, аудит.

После Фазы 5: полный MVP.

### После Фазы 3

- [ ] Все алгоритмы process mining реализованы как чистые функции.

## Оценки трудоёмкости

Грубая оценка для одного разработчика с использованием Claude Code в качестве ассистента.

| Фаза | Задач | Оценка | Накопл. |
|------|-------|--------|---------|
| 1    | 8     | 2 недели | 2 нед   |
| 2    | 8     | 3 недели | 5 нед   |
| 3    | 8     | 3 недели | 8 нед   |
| 4    | 8     | 4 недели | 12 нед  |
| 5    | 8     | 3 недели | 15 нед  |

**Итого: ~15 недель = 3.5-4 месяца** при условии 8 рабочих часов в день и наличия Claude Code.

Эти оценки оптимистичны. С учётом обучения, неожиданных проблем интеграции, доработок UX — реалистичный срок **5-6 месяцев**.

## Рекомендации по работе с Claude Code

1. **Одна задача за раз.** Не передавайте Claude Code сразу T01-T05. Берите T01, доводите до зелёных тестов, потом T02.
2. **Контекст — нужные файлы ТЗ.** Перед каждой задачей подгружайте в контекст только релевантные файлы: например, для T11 (xlsx loading) — `00_OVERVIEW`, `01_DATA_MODEL` (для column_mapping), `02_DOMAIN_LOGIC` (раздел loading), `tasks/T11_xlsx_loading.md`.
3. **Golden tests — ваш страховой полис.** При любых сомнениях в правильности алгоритма — запускайте `pytest tests/golden`. Если зелёные — алгоритм точно работает.
4. **Не оптимизируйте раньше времени.** Сначала — корректность, потом — производительность. Claude Code часто пишет работающий код не самый эффективный — это нормально для MVP.
5. **Регулярные git-коммиты.** После каждой пройденной задачи (или субтаска) — коммит. Если что-то сломалось — `git reset --hard` к стабильной точке.
6. **README и комментарии.** Просите Claude Code писать docstring к функциям и обновлять README, когда добавляете новые команды Makefile или env-переменные.
